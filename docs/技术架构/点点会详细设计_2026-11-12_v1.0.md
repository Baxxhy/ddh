## 1. 设计范围与软件工程方法

### 1.1 目标和边界

本设计把概要设计中的用户功能分解为可实现、可测试的模块、状态、数据和接口。用户无需注册即可开始练习，可以亲自操作、犯错、返回、修改、重试、求助、朗读提示并查看模拟结果。所有数据和二维码均为演示用途，系统不连接真实医院、公交或支付服务，不产生预约、乘车或资金交易。

第一版不建设登录、跨设备同步、长期学习档案、历史记录、统计与推荐、家属端、管理后台、额外练习模式或其他场景。MySQL 只保存场景配置、知识资料和有过期时间的当前练习会话；临时操作历史仅用于本次返回，不作为用户学习记录。

### 1.2 需求追踪

| 需求 ID | 用户可感知能力 | 设计位置 | 验收用例 ID |
| --- | --- | --- | --- |
| R01 | 直接选择三个场景并开始练习 | 2、3、4 | T01、T02、T03 |
| R02 | 亲自完成模拟点击、选择、输入、核对 | 3、4、5 | T01、T02、T03 |
| R03 | 点错后返回、修改、重试和重新开始 | 3、4、6 | T04、T05、T06 |
| R04 | 请求当前步骤的文字指导 | 7、8 | T07、T08 |
| R05 | 朗读、暂停或停止提示 | 5、7 | T09 |
| R06 | 看到明确的模拟结果且无真实业务后果 | 3、4、9 | T01、T02、T03、T10 |
| R07 | 适老化、键盘与屏幕阅读器可用 | 5、10 | T11、T12 |

### 1.3 分层和依赖原则

```text
React 页面与组件 → 前端 API 客户端 → FastAPI 路由
                                      ↓
                              练习应用服务
                              ↙          ↘
                        场景规则引擎    指导服务
                              ↓          ↓
                         MySQL 仓储   检索 + LangGraph
```

场景规则引擎是模拟结果的唯一判定者。指导服务可以读取当前步骤和允许动作，但不能直接改变练习状态。前端只展示后端返回的权威状态，不自行判定“预约成功”“乘车成功”或“支付成功”。模块之间通过明确的数据结构通信，避免页面直接访问数据库或模型 API。

## 2. 模块职责与目录建议

| 模块 | 责任 | 不负责 |
| --- | --- | --- |
| 场景目录 | 提供三个场景的名称、任务、版本和演示资料 | 保存用户进度 |
| 状态引擎 | 校验动作、执行转移、清理依赖选择、产生模拟结果 | 生成自然语言答案 |
| 会话服务 | 创建临时会话、检查过期与版本、保存当前状态和回退栈 | 长期学习分析 |
| 指导服务 | 根据步骤检索知识、调用单 Agent、校验输出并降级 | 决定业务成功或替用户点击 |
| FastAPI 路由 | 请求验证、调用应用服务、统一响应与错误码 | 编写业务规则 |
| React 练习界面 | 展示任务、模拟手机、操作反馈、辅助控件 | 推测服务端状态 |
| 语音适配层 | 朗读屏幕上已展示的提示，控制暂停、停止、重听 | 生成不同于文字的指导 |

建议在 `frontend/src/` 中按 `features/scenarios`、`features/practice`、`features/guidance`、`shared` 组织；在 `backend/app/` 中按 `api`、`domain`、`services`、`repositories`、`ai` 组织。实施时以实际代码规模为准，不为目录形式提前拆出空抽象。场景规则与演示数据必须有独立版本，便于测试和日后调整。

## 3. 公共练习状态设计

### 3.1 状态数据

```text
PracticeState {
  scenarioId: hospital | bus | payment
  scenarioVersion: string
  nodeId: string
  selections: 仅本场景需要的演示选择或输入
  returnStack: 最多 20 个可返回快照
  revision: 非负整数
  feedback: { kind: info | error | success, message: string } | null
  result: 模拟结果 | null
}
```

`nodeId` 与 `selections` 由后端维护。`returnStack` 仅保存本次练习中的必要状态，重新开始时清空。`revision` 每次成功改变状态后递增，用于识别重复点击和旧页面提交；错误动作如果不改变状态，保持原值。所有时间和金额使用明确的数据类型：时间用带时区的时间戳或演示时段 ID，金额以整数分存储和比较，不使用浮点数。

### 3.2 动作处理规则

1. 前端只提交当前页面列出的 `actionId` 和必要值，连同当前 `revision`。
2. 后端先校验会话、过期时间、场景版本、动作是否属于当前节点，再校验输入值是否存在于演示数据中。
3. 合法动作按场景状态机转移，并把可返回的旧状态入栈；需要修改上游选择时，清除所有依赖该选择的下游字段。
4. 不合法动作返回可理解的错误反馈和当前权威状态，不跳到下一步，不修改已填内容。
5. 重复提交旧 `revision` 返回冲突和当前权威状态；前端据此刷新页面，不再次执行动作。
6. 只有用户亲自触发最终确认，且服务端核对所有任务条件，才能进入模拟成功节点。

### 3.3 返回、修改和重试

- **返回上一步：** 弹出最近的可返回快照；在演示支路页面返回原入口。已输入且仍适用的内容保留。
- **修改指定项：** 从核对页进入相应的选择页，修改后重新经过必要的下游步骤；医院改变时清空科室、医生、时段，科室改变时清空医生、时段，医生改变时清空时段；商户改变时清空金额。
- **错误后重试：** 输入或模拟扫码失败时留在可操作节点，给出错误原因和下一步；不清空无关选择。
- **重新开始：** 清空本次状态、回退栈、结果和旧提示，回到场景第一节点；通过新的 `revision` 防止旧操作继续生效。
- **退出：** 回到场景选择页并关闭当前会话；无需弹出多余确认。再次进入时新建会话。

### 3.4 统一响应状态

每个状态返回 `nodeId`、页面标题、步骤序号与总数、当前任务、可用动作及展示资料、已选摘要、反馈、`canGoBack`、`isComplete` 和 `revision`。前端不使用硬编码的“第几步成功”逻辑，但可以按 `nodeId` 选择模拟页面组件。每个节点的页面都显示“模拟练习”标识。

## 4. 三个场景的详细状态机

场景配置使用稳定的动作和节点 ID；展示文案可单独调整。下表中的演示名称和金额是设计样例，实施时作为版本化的演示数据维护，不能伪装成实时医院号源、公交凭证或真实商户。

### 4.1 医院预约挂号

**任务样例：** 在“演示医院 A”预约“内科／普通门诊／演示时段 A”。任务目标在开始页和核对页可查看；日期使用“演示时段 A”等固定标识，页面明确显示其模拟属性，不展示容易被误认为真实号源的实时库存。

| 节点 | 页面与可操作内容 | 合法动作 → 下个节点 | 错误与恢复 |
| --- | --- | --- | --- |
| H0 | 模拟医疗服务首页 | `open_registration` → H1 | 点其他服务进入通用演示支路 HX，可返回 H0 |
| H1 | 演示医院列表 | `select_hospital(id)` → H2 | 无效 ID 留在 H1；选非目标医院也可继续探索，核对时提示修正 |
| H2 | 所选医院的演示科室 | `select_department(id)` → H3 | 科室与医院不匹配时留在 H2；返回可换医院 |
| H3 | 所选科室的演示医生或门诊类型 | `select_doctor(id)` → H4 | 医生与科室不匹配时留在 H3 |
| H4 | 演示就诊时段列表 | `select_slot(id)` → H5 | 时段无效时留在 H4；返回可换医生 |
| H5 | 医院、科室、医生、时段核对页 | `confirm_registration` → H6；`edit_*` → 对应节点 | 信息缺失或与任务不符时不确认，指出需要修改的项目 |
| H6 | 模拟预约成功及全部已选资料 | `restart` → H0；`exit` → 场景选择 | 明确显示“没有产生真实挂号记录” |
| HX | 非任务服务的演示页 | `back` → 进入 HX 前的节点 | 无提交或真实跳转能力 |

**不变量：** H5 必须具备医院、科室、医生、时段四项有效选择；H6 必须由 H5 的确认动作进入。医生必须属于所选科室，时段必须属于所选医生。用户选择不符合任务目标时，应允许在 H5 返回修改，不把探索过程误判为系统错误。

### 4.2 公交乘车码

| 节点 | 页面与可操作内容 | 合法动作 → 下个节点 | 错误与恢复 |
| --- | --- | --- | --- |
| B0 | 模拟生活服务首页 | `open_travel` → B1 | 其他服务进入 BX，可返回 B0 |
| B1 | 出行服务页 | `open_transport` → B2 | 返回 B0 |
| B2 | 公交与地铁入口 | `choose_bus` → B3；`choose_metro` → BM | 地铁页可返回 B2 或切换公交 |
| B3 | 公交服务页 | `open_bus_code` → B4 | 返回 B2 |
| B4 | 显著标注“无效演示图形”的乘车码页 | `align_and_scan` → B6 | `scan_not_aligned` 留在 B4 并提示重新对准；不随机决定成功 |
| B6 | 模拟乘车成功页 | `restart` → B0；`exit` → 场景选择 | 明确显示“没有产生真实乘车记录” |
| BM/BX | 地铁或其他服务演示支路 | `back` → 前一节点；BM 可 `choose_bus` → B3 | 不把错误入口当成完成 |

**演示码约束：** 展示图形不按可识别的真实二维码格式生成，不包含乘车 Token、支付链接或有效业务编码。“模拟扫码”由本地页面动作和后端状态规则完成，不能调用相机扫描真实乘车码。

### 4.3 扫码支付

**任务样例：** 向“演示商户 A”支付 **12.50 元模拟金额**。该金额是版本化练习资料，不代表真实交易。

| 节点 | 页面与可操作内容 | 合法动作 → 下个节点 | 错误与恢复 |
| --- | --- | --- | --- |
| P0 | 模拟支付应用首页 | `open_scan` → P1 | 其他入口进入 PX，可返回 P0 |
| P1 | 演示扫码页，显示多个明确标注的演示码 | `scan_demo_code(id)` → P2 | 不识别真实支付二维码；无效 ID 留在 P1 |
| P2 | 演示收款方信息 | `continue_to_amount` → P3 | 用户可以返回更换演示码 |
| P3 | 输入模拟金额 | `set_amount(value)` → P4 | 空值、非数字、零、负数、超过两位小数或超出演示上限时留在 P3，并说明如何改正 |
| P4 | 商户、金额核对页 | `confirm_payment` → P5；`edit_amount` → P3；`edit_merchant` → P1 | 与任务目标不符时不得确认，突出需要修改的项目 |
| P5 | 模拟支付成功页 | `restart` → P0；`exit` → 场景选择 | 明确显示“没有发生资金交易” |
| PX | 非任务入口的演示页 | `back` → P0 | 不提供真实支付或银行卡录入能力 |

**不变量：** P4 必须同时显示商户与金额；P5 只能由 P4 的显式确认进入。金额以整数分比较，例如 `12.50` 解析为 `1250`，显示时保留两位小数。前后端均不收集支付密码、银行卡号或真实支付凭证。

## 5. 前端详细设计

### 5.1 页面组成

| 页面 | 核心内容 | 关键交互 |
| --- | --- | --- |
| 场景选择 | 三个大入口，名称为“医院挂号”“公交乘车码”“扫码支付” | 选择后查看任务 |
| 任务说明 | 一句任务目标、模拟提醒、“开始练习” | 创建会话并进入第一节点 |
| 练习页面 | 模拟手机区域、当前步骤、文字反馈、固定的返回／求助／退出操作 | 提交动作、修改、重试、朗读 |
| 结果页面 | 模拟成功标题、关键选择、无真实后果说明 | 再练一次、选择其他场景 |

任务说明和结果可以由同一练习路由按阶段展示；不增加独立的“我的学习”或 AI 聊天页面。模拟手机区域只复现教学所需的关键控件，不复制真实第三方品牌界面或显示其登录、支付凭证。

### 5.2 组件与状态

建议共用 `ScenarioTile`、`PracticeShell`、`StepProgress`、`ActionButton`、`FeedbackMessage`、`HelpPanel`、`SpeechControls`、`SimulationBadge`、`ResultSummary`，并按场景拆分 `HospitalScreen`、`BusScreen`、`PaymentScreen`。组件只处理展示和用户输入；状态转移由后端决定。只有在跨多个页面共享状态确有复杂性时再引入 Zustand。

前端临时状态包括当前服务端状态、会话 Token、当前输入草稿、请求中的按钮、指导文字与来源、语音播放状态。Token 仅保存在当前标签页运行内存中；刷新后可以重新开始，不宣称支持跨设备或继续上次练习。返回到上一步时，适用的输入草稿由后端状态和本地草稿共同恢复。

### 5.3 操作时序与异常

```text
用户点击 → 禁用本次提交按钮 → 发送 actionId + revision
        → 成功：替换为后端权威状态，读出/显示反馈由用户自行触发
        → 409：获取响应中的当前状态，提示“页面已更新，请再试一次”
        → 网络失败：保持当前页面和输入，显示“没有提交成功，请重试”
```

前端不自动连续提交、不自动朗读、不在错误后自动跳转。请求处理中允许查看现有文字，但防止重复确认。指导请求与场景操作分离；AI 慢或不可用时不阻塞返回、修改、重新开始。

### 5.4 适老化落地

- 正文默认 20–22 CSS px，重要信息 22–26 CSS px；大字模式可切换，布局在 200% 文字放大后仍可操作。
- 正文行高推荐 1.5–1.7，普通文字对比度至少 4.5:1。主要触控目标建议至少 60×60 CSS px，其他目标至少 44×44 CSS px。
- 一屏聚焦一个任务；主操作使用文字标签，按钮保持间距，返回／求助／退出位置稳定，多步骤显示进度。
- 错误信息说清“哪里不对”和“怎么改”，同时使用文字而非单靠颜色。
- 所有关键控件有键盘焦点、可访问名称和屏幕阅读器可理解的状态；动画尊重系统减少动态效果。
- 语音朗读必须由用户主动触发，提供暂停、继续、停止与重听。浏览器不支持时保留全部文字。

## 6. API 与会话契约

以下是拟实现的版本化接口；实现时以 OpenAPI 生成文档与契约测试为准。所有请求和响应使用 UTF-8 JSON，错误中不返回堆栈、模型密钥或数据库内部信息。

| 方法与路径 | 输入 | 成功响应 | 失败状态 |
| --- | --- | --- | --- |
| `GET /api/v1/scenarios` | 无 | 三个场景的 ID、名称、任务摘要和版本 | 500 |
| `GET /api/v1/scenarios/{id}` | 场景 ID | 任务、模拟说明和开始页资料 | 404 |
| `POST /api/v1/practice/sessions` | `{scenarioId}` | 会话 Token、初始 `PracticeState` | 404、422、503 |
| `POST /api/v1/practice/actions` | Token 请求头；`{actionId,value?,revision}` | 更新后的 `PracticeState` | 409、410、422 |
| `POST /api/v1/practice/back` | Token 请求头；`{revision}` | 回退后的 `PracticeState` | 409、410、422 |
| `POST /api/v1/practice/restart` | Token 请求头；`{revision}` | 初始 `PracticeState` | 409、410 |
| `POST /api/v1/guidance` | Token 请求头；`{question?}` | 指导文字、来源、生成方式 | 410、422、429 |
| `POST /api/v1/practice/exit` | Token 请求头 | `{closed:true}` | 410 |

Token 使用至少 256 位密码学随机数生成，服务端只存其 SHA-256 摘要；前端通过 `X-Practice-Session` 请求头发送，不写入 URL、持久化浏览器存储或日志。无登录并不意味着会话可被他人猜测或读取。生产环境要求 HTTPS、受限 CORS 和合理的指导接口限流。

### 6.1 动作请求与状态响应示例

```json
{
  "actionId": "select_department",
  "value": "department-demo-internal",
  "revision": 2
}
```

```json
{
  "scenarioId": "hospital",
  "scenarioVersion": "1.1",
  "nodeId": "H3",
  "revision": 3,
  "step": { "current": 4, "total": 7, "title": "选择医生" },
  "selections": { "hospitalId": "hospital-demo-a", "departmentId": "department-demo-internal" },
  "actions": [{ "id": "select_doctor", "label": "选择医生", "options": [] }],
  "feedback": null,
  "canGoBack": true,
  "isComplete": false,
  "simulationNotice": "模拟练习，不会产生真实预约"
}
```

示例中的 `options` 在实际响应中由场景演示数据填充；不得让前端自行伪造医院或医生选项。请求值只允许符合当前节点配置的 ID 或输入格式。错误响应使用统一结构 `{code,message,state?}`：`409 REVISION_CONFLICT` 附当前状态，`410 SESSION_EXPIRED` 提示重新开始，`422 INVALID_ACTION` 或 `INVALID_INPUT` 附可纠正信息。未知系统异常返回通用提示并记录不含密钥的服务器诊断信息。

### 6.2 指导响应

```json
{
  "text": "请先在科室列表中找到‘内科’，点选后再选择医生。",
  "mode": "model",
  "sourceIds": ["hospital-department-step-v1"],
  "suggestedActionId": "select_department"
}
```

`mode` 取 `model` 或 `fallback`。`sourceIds` 必须是实际检索到并用于回答的知识片段 ID。若模型未配置、超时或校验失败，接口返回 200 与维护过的步骤提示，`mode=fallback`；前端显示“步骤提示”，不冒称 AI 已生成答案。用户问题限制长度，例如 200 个字符；指导只讨论当前模拟操作，不回答真实诊疗、票价或支付承诺。

## 7. 数据库与知识库详细设计

### 7.1 MySQL 表

| 表 | 关键列 | 约束与用途 |
| --- | --- | --- |
| `scenario_versions` | `scenario_id VARCHAR(32)`、`version VARCHAR(16)`、`title`、`task_text`、`config_json JSON`、`active BOOLEAN` | `(scenario_id,version)` 唯一；三个场景的版本化步骤和演示资料 |
| `practice_sessions` | `id BIGINT`、`token_hash CHAR(64)`、`scenario_id`、`scenario_version`、`node_id`、`selections_json JSON`、`return_stack_json JSON`、`revision INT`、`result_json JSON NULL`、`expires_at DATETIME`、`created_at`、`updated_at` | `token_hash` 唯一；只保存临时状态，按 `expires_at` 清理 |
| `knowledge_chunks` | `id VARCHAR(80)`、`scenario_id`、`node_id NULL`、`title`、`body TEXT`、`keywords_json JSON`、`version`、`active BOOLEAN` | 经人工整理的步骤、错误恢复、安全提醒；ID 可作为指导来源 |

使用迁移脚本建表，使用受版本控制的种子数据初始化三个场景和知识片段；不要在启动时无条件覆盖已有数据。`practice_sessions` 不含用户姓名、身份证号、银行卡号、支付密码或长期学习分数。会话有效期目标为 2 小时无活动；每次合法操作更新到期时间，定期清理过期行。会话失效后返回 410，界面提供“重新开始”。该有效期是实现默认值，部署时可配置。

### 7.2 RAG 检索

知识资料按“场景 → 节点 → 问题类型”组织，首批只覆盖三个场景。检索先以场景和当前节点过滤，再对标题、关键词和正文进行中文关键词或字符片段匹配，返回最多 3 个相关片段；若当前节点无匹配，回退到该场景通用安全片段。由于语料规模小，第一版可使用可测试的本地检索器，不强制引入向量数据库或额外模型。检索结果连同来源 ID 一起进入提示词，并在输出中校验引用是否真实存在。

知识库内容不得出现真实挂号承诺、真实票价、真实支付结果或指向真实交易的操作。知识片段和场景版本应能对应，修改规则时同步检查相关片段与测试用例。

### 7.3 LangGraph 单 Agent 流程

```text
读取权威会话状态 → 检索当前步骤知识 → 判断模型是否可用
                                  ├─ 可用：生成结构化指导 → 校验 → 返回
                                  └─ 不可用或校验失败：维护过的步骤提示 → 返回
```

输入：场景 ID、节点 ID、任务目标、当前选择、合法下一步动作、用户问题和检索片段。输出：`text`、`suggestedActionId`、`sourceIds`。校验规则包括：文字非空且简短、建议动作属于当前节点、来源 ID 属于本次检索结果、不含要求真实支付或提交敏感信息的内容。模型调用封装在后端适配层，模型名称、兼容接口地址和 API Key 来自环境变量。生成超时目标为 8 秒；超时或网络异常进入降级路径，不阻断练习。AI 不写 `practice_sessions`，不执行动作，也不决定模拟结果。

## 8. 安全与异常处理

| 风险或异常 | 处理规则 | 用户看到的反馈 |
| --- | --- | --- |
| 真实业务误认 | 所有页面、码图形和结果页标识模拟；无真实接口调用 | “这是模拟练习，不会产生真实记录” |
| 重复点击或旧页面提交 | `revision` 冲突，不重复执行确认 | “页面已更新，请再试一次” |
| 输入错误 | 服务端验证合法 ID、金额格式、长度和范围 | 具体指出应修改的内容 |
| 网络断开 | 不预先改变成功状态，保留输入 | “没有提交成功，请检查网络后重试” |
| 会话过期 | 返回 410，清除本地 Token | “本次练习已结束，请重新开始” |
| 模型或检索异常 | 使用维护过的步骤提示，记录无密钥的诊断 | “当前使用步骤提示”及可操作建议 |
| 浏览器无语音能力 | 不调用朗读，文字保持可见 | “此浏览器暂不支持朗读” |
| 恶意问题或模型越界 | 限长、过滤、结构化校验与动作白名单 | 回到当前步骤的安全提示 |

第一版不采集真实个人敏感资料，不记录完整用户自由提问或模型密钥。诊断日志只保留必要的请求 ID、错误类别、场景与节点，不输出会话 Token 原文。数据库使用最小权限账号；前后端仅开放必要来源与接口。演示图形不可被真实扫码平台识别为有效支付或乘车码。
