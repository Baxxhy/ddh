# 第二阶段接口与状态实现

版本：V1.0  
日期：2026-11-13

依据概要设计V1.2、详细设计V1.1及项目负责人第二阶段指令。本说明记录实现与设计的对应关系，不覆盖历史设计。

## 状态与持久化

统一纯函数引擎负责合法动作、选项关系、金额、目标核对、修改依赖和完成条件。医院H0—H6/HX、公交B0—B4/B6/BM/BX、支付P0—P5/PX均实现。演示资料保存为scenario_versions的2.0版本，engineVersion=2；1.0资料保留，不改写历史场景。金额以整数分存储，输入是最多两位小数的十进制字符串，范围为0.01—1000.00元。

scenario_current用场景ID主键指向明确的当前版本。列表和详情都通过该指向查询；不会把多个启用版本重复展示，也不使用字符串倒序选版本。迁移初次从旧数据回填映射时按数字版本分段比较；之后由明确的版本指向控制。种子程序首次插入2.0并切换指向，重复执行不覆盖已有版本。每个练习会话固定保存scenario_version，不随当前版本变化。

practice_sessions复用原表，并增加closed_at与expires_at索引。随机令牌为32字节熵，服务端只存SHA-256；前端只在React内存中保存令牌，不写URL、浏览器持久化存储或日志。UTC时间以不带时区的DATETIME保存，合法状态变化续期两小时。刷新浏览器需新开练习，旧会话自然过期。

returnStack最多20个页面路径节点，已选内容作为当前权威selections保留；返回不恢复已失效的下游选择。上游选择变化时同时清空依赖字段并裁剪失效页面路径。非法操作不落库、不增加revision。错误反馈随错误响应返回，不作为长期记录。

## API

| 方法 | 路径 | 输入或输出 |
| --- | --- | --- |
| POST | /api/v1/practice/sessions | `{scenarioId}` → `{sessionToken,state}` |
| GET | /api/v1/practice/state | 当前会话状态 |
| POST | /api/v1/practice/actions | `{revision,actionId,value?}` → 状态 |
| POST | /api/v1/practice/back | `{revision}` → 返回后的状态 |
| POST | /api/v1/practice/restart | `{revision}` → 清空选择及结果，revision递增 |
| POST | /api/v1/practice/exit | `{revision}` → `{closed:true}`，关闭会话 |

除创建外使用X-Practice-Session请求头。状态使用统一Pydantic模型，包含scenarioId、scenarioVersion、nodeId、title、task、step、actions、selections、selectedSummary、returnStack、revision、feedback、result、canGoBack、isComplete、simulationNotice。

练习错误统一为`{code,message,state}`。不存在场景404，旧revision为409并携带当前状态，失效令牌或会话410，非法动作/输入422，数据库/场景版本不可用503。结构校验失败时state为空，前端保留已有页面。

同一会话的读取更新使用MySQL SELECT FOR UPDATE，版本核对、业务规则、状态写入和revision增加在同一事务中完成。重复成功确认不能生成第二份结果。前端同步提交锁阻止重复点击，但后端事务校验始终独立有效。网络失败不自动重放动作，用户可读取权威状态再继续。

## 前端组件

PracticeProvider统一管理内存会话、请求锁和异常状态；PracticeActions由服务端动作渲染真实选项与金额输入，三个场景屏幕共用布局和反馈。成功页只由服务端result驱动。公交演示图形是带文字的无效图形，不生成二维码、不调用摄像头。

Taro UI的AtTag通过官方React H5 View组件接入现有Vite工程；没有更换构建框架。操作按钮和表单保留原生语义及键盘能力。本轮没有整体迁移或美化原首页。字体沿用仓库规范，前端开发、预览、测试固定5173。
