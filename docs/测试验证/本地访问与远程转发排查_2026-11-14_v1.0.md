# 本地访问与远程转发排查

版本：V1.0  
日期：2026-11-14

用户在Windows Codex预览打开点点会时，页面显示localhost随机本地端口及ERR_CONNECTION_RESET。最初发现远程前后端进程未运行，恢复进程后，用户仍无法访问；因此服务器返回200不能视为用户端问题已经解决。

## 实际证据

- 远程Vite固定5173，FastAPI8017；HTML、健康检查及三个场景接口正常。
- 最初127.0.0.1可用，::1不可用，而远程localhost优先解析为::1。改为双栈监听::后，IPv4及IPv6均返回200；Vite默认配置与.env.example同步更新，端口仍固定5173。
- 远程Chromium通过http://localhost:5173打开页面，读取三个场景并进入医院介绍成功。
- 类型检查、ESLint、构建均通过。
- SSH服务端AllowTcpForwarding=yes、DisableForwarding=no、PermitOpen=any；授权密钥没有restrict/no-port-forwarding限制。
- SSH日志多次出现cannot listen to port:7890，IPv4/IPv6的7890已被现有SSH转发占用。此为新的转发失败线索，是否使客户端预览退出仍需客户端验证。

## Windows端进一步验证

如果本机SSH配置的远程别名为4x3090，在Windows PowerShell运行并保持窗口打开：

```powershell
ssh -N -o ExitOnForwardFailure=no -L 127.0.0.1:5173:127.0.0.1:5173 4x3090
```

再用外部浏览器打开http://127.0.0.1:5173/。此命令将本机5173转到远程5173，没有更换前端端口。别名应以用户本机SSH配置为准。若仍显示7890转发失败，需要核对对应Host下的RemoteForward配置和现有连接。此处未自动关闭任何已有SSH代理，也未修改用户Windows配置。

用户电脑上的显式转发、外部浏览器和Codex预览链路尚未验证。问题不能标记为端到端修复完成。
