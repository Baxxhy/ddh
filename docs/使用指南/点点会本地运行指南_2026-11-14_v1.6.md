# 点点会本地运行指南

版本：V1.6  
日期：2026-11-14

当前可以亲自完成医院挂号、公交乘车码、扫码支付三个模拟任务，并返回、修改、重试、重新开始和退出。所有信息均为虚拟资料，不产生真实预约、乘车或交易。AI、知识检索、语音功能尚未开发。

## 准备与初始化

环境：Linux、Node.js 20.19+或22.12+、Python 3.12、Docker Compose和MySQL 8.4。首次在仓库根目录运行：

```bash
cp .env.example .env
```

编辑.env中的本地密码，保持DATABASE_URL与MYSQL配置一致，特殊字符需要URL编码。不要覆盖已有的有效.env。然后在根目录运行：

```bash
docker compose up -d --wait mysql
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.lock
.venv/bin/python -m alembic -c backend/alembic.ini upgrade head
.venv/bin/python -m backend.app.seed
npm --prefix frontend ci
```

迁移复用旧数据，新增当前版本指向和会话关闭字段；种子数据保留1.0并加入2.0模拟配置。重复初始化不重复写入。frontend/.npmrc记录Taro UI在此Web工程使用的peer依赖安装方式，npm ci按锁文件复现，不会引入原生App构建。

## 分别启动

后端在根目录运行：

```bash
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

另一个终端：

```bash
npm --prefix frontend run dev
```

前端固定5200，访问http://localhost:5200。手机与电脑同一局域网时访问`http://电脑局域网IP:5200`。前端双栈监听::，经相对/api路径代理至本机后端；手机不会请求自身localhost。MySQL仅监听电脑127.0.0.1:3306。

如果8000已占用，可将后端改为8017并在.env设置`API_PROXY_TARGET=http://127.0.0.1:8017`，重启前端。前端禁止改用其他端口；5200占用时先确认占用进程，不能另开其他前端端口。VITE_API_BASE_URL默认为/api/v1；VITE_HOST控制前端监听地址。修改配置后重启Vite。手机无法打开时检查IP、同一网络、网络隔离和5200的本地防火墙设置。

## 浏览器操作

从首页选择场景，在介绍页点击开始练习。每一步由用户操作驱动。医院任务为演示医院A、内科、普通门诊、演示时段A（周一上午）；支付任务为演示商户A、12.50元。公交按出行、交通服务、公交、公交乘车码进入，再尝试模拟扫码。

选错后可返回或在核对页修改。只有符合目标并主动确认才生成模拟结果。重新开始会重置当前练习；退出会关闭会话。刷新页面会丢失内存令牌，应重新开始。网络故障后可点击读取当前页面，确认服务端状态再操作。

## 验证命令

```bash
.venv/bin/python -m pytest backend/tests -q
.venv/bin/python -m alembic -c backend/alembic.ini check
npm --prefix frontend run typecheck
npm --prefix frontend run lint
npm --prefix frontend run build
cd frontend
npx playwright install --with-deps chromium
npm test -- --workers=1
```

浏览器测试需要前后端已启动，固定访问5200。默认后端测试跳过真实MySQL集成组；要验证并发及持久化，先准备独立验证数据库，以下命令使用容器内的本地环境变量，不输出密码：

```bash
docker compose exec -T mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "CREATE DATABASE IF NOT EXISTS ddh_phase1_verify; GRANT ALL ON ddh_phase1_verify.* TO '\''ddh'\''@'\''%'\'';"'
DDH_MYSQL_TEST=1 .venv/bin/python -m pytest backend/tests -q
```

以上授权命令假定本地用户名为ddh；自定义MYSQL_USER时需相应修改用户名。集成测试通过DATABASE_URL取得连接配置，使用独立的ddh_phase1_verify数据库，不清空主库。测试会保留用于验证的版本资料和未到期临时会话。

## 临时会话清理

在仓库根目录运行：

```bash
.venv/bin/python -m backend.app.practice.cleanup
```

每次最多清理500条过期或已关闭会话，删除前再次检查失效条件，保留仍有效会话。本地可手动运行；持续运行时可用cron每30分钟执行此命令，先cd到仓库根目录。不需要启动额外常驻服务。

数据库无法连接时检查容器健康状态和DATABASE_URL；没有场景或场景未准备好时先执行迁移和seed。旧页面冲突会返回服务端当前状态，应按更新后的页面继续。第三方Starlette/httpx测试弃用警告不影响本轮测试结果。

## 第三阶段页面与辅助操作

首页三个完整入口可点击，进入任务说明后点击开始练习。界面右上角“大字”按钮可切换更大字号，整个应用均生效；不影响系统或浏览器本身的字号设置。练习页的任务默认收起，可通过“本次任务”展开查看。

医院分别呈现医院、科室、门诊、时段列表和预约信息核对。公交提供生活服务、交通类型、公交乘车码和虚拟扫码器；“未对准”会给出错误反馈，用户可以主动重新扫码。支付分别呈现演示商户、收款方核对、金额输入和付款信息核对。所有选项仍来自后端，不接入真实第三方服务。

返回操作位于顶部导航；重新开始和退出位于内容之后，不浮动遮挡内容。医院和支付的修改页面按前后层级返回，同值重选会保留有效业务信息并清理旧的前进路径。探索支路明确显示“可返回继续练习”，不展示完成进度。成功页展示服务端结果和摘要，提供再练一次、返回首页。

键盘可用Tab移动焦点、Enter操作按钮；任务折叠使用浏览器原生details语义。金额输入框有明确标签，页面切换将焦点移至标题；错误反馈可聚焦并被辅助技术识别。窄屏与大字模式允许纵向滚动，未设置覆盖内容的固定底栏。尚未执行实体Android手机或真实屏幕阅读器检查。

新增第三阶段检查：`npm --prefix frontend test -- tests/accessibility.spec.ts --workers=2`。运行全量测试仍使用前文命令；不得更换5200端口。

## 固定端口与Windows远程访问

项目负责人于2026-11-14明确将前端永久端口改为5200，替代此前5173约定。开发、预览、浏览器自动测试和CORS模板统一5200；端口被占用时报错，不自动换端口。旧版文档的5173仅是历史记录。

前端运行在远程主机时，Windows本机需有对应转发。若SSH别名为4x3090，在Windows PowerShell执行并保持窗口打开：

```powershell
ssh -N -o ExitOnForwardFailure=no -L 127.0.0.1:5200:127.0.0.1:5200 4x3090
```

然后在外部浏览器访问`http://127.0.0.1:5200/`。SSH别名按用户实际配置替换。服务器端返回200不代表本机转发已成功；本机仍需验证。
