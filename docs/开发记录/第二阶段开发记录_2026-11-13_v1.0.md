# 第二阶段开发记录

版本：V1.0  
日期：2026-11-13

## 需求与指令

项目负责人验收第一阶段后，明确要求本轮实现三个场景的完整模拟操作、返回修改和重试、MySQL临时会话、事务一致性与多版本问题修复，并完成测试和推送；本轮不进入第三阶段、不接入AI或语音。

## 实际增量

1. 拉取main并阅读AGENTS、概要设计V1.2、详细设计V1.1、开发计划V1.2及第一阶段验收记录，检查已有模型、API、前端和端口。
2. 新增统一纯函数引擎、带层级关系的虚拟医院资料和演示支付资料。保留场景1.0，新增2.0，增加scenario_current显式版本映射。
3. 用原practice_sessions表保存状态、选择、路径和结果，增加关闭时间及到期索引。令牌哈希、两小时有效期、行锁、revision检查与提交在同一事务中执行；提供批量过期清理命令。
4. 增加创建、状态读取、操作、返回、重启、退出接口及Pydantic响应。前端共用PracticeProvider、操作渲染和反馈；三个场景组件提供真实点击/选择/输入与服务端结果展示。
5. Taro UI状态标签使用官方React H5 View桥接，保留Vite。按实际需要补充类型声明，解决官方H5深层入口缺少声明的类型检查问题。保留中文系统/微软雅黑、英文Times New Roman及5173端口限制。
6. 初步规则测试22项通过后，增加真实MySQL集成测试到31项；补充医院逐级修改、各类错误目标和接口边界，最终42项通过。浏览器先跑通10项，再加入409同步、断网恢复和练习页面放大检查，最终12项通过。
7. 审查清理逻辑时补上删除前的失效条件复查，避免清理读取到期列表后误删刚被续期的会话。更新原生控件与Taro所需依赖锁文件，移除没有使用的直接依赖。
