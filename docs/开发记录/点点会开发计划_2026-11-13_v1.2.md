# 点点会开发计划

**版本：** V1.2  
**日期：** 2026 年 11 月 13 日  
**依据：** [概要设计 V1.2](../技术架构/点点会概要设计_2026-11-12_v1.2.md)、[详细设计 V1.1](../技术架构/点点会详细设计_2026-11-12_v1.1.md)

第一版只实现医院预约挂号、公交乘车码、扫码支付三个模拟场景。应用形态统一为 **React + TypeScript + Vite 移动端优先响应式 Web 应用**：手机竖屏优先，桌面浏览器兼容；界面按手机应用设计。前后端分离，本地支持电脑调试和同一局域网内的手机访问。按下面的顺序小步开发；每完成一个可验证的改动，就提交并推送。V1.0、V1.1 保留作为历史版本。

| 阶段 | 主要工作 | 完成标志 |
| --- | --- | --- |
| 1. 搭建项目基础 | 建立 React + TypeScript + Vite 前端、FastAPI 后端和 MySQL 场景数据结构；准备三个场景的演示数据、环境变量模板及启动说明。配置 Vite 局域网访问和到 FastAPI 的 `/api` 代理；完成可读取场景列表的首页与场景介绍页；使用 React Router、Lucide，补齐 Alembic 迁移、三张基础表、场景详情接口和自动化测试。 | 前后端能分别启动；电脑和同一局域网内的手机可打开基础页面，并从 API 读取三个演示场景。 |
| 2. 实现模拟流程 | 按详细设计实现三个场景的步骤、点击与输入规则；完成返回、修改、重试、重新开始和模拟结果接口。 | 三个场景都能从开始走到模拟成功；选错后可以恢复。 |
| 3. 完成适老化界面 | 实现场景选择、任务说明、模拟练习和结果页面；统一大字、大按钮、进度、反馈和导航。 | 手机与桌面都能完成三个流程，主要操作清楚、易点。 |
| 4. 接入指导与语音 | 整理三个场景的知识片段，接入 RAG 与 LangGraph 单 Agent；加入模型不可用时的步骤提示和用户主动触发的语音朗读。 | 当前步骤能得到对应文字提示；朗读可暂停、停止和重听。 |
| 5. 联调与功能验收 | 联调前后端，检查三条完整流程、典型错误和恢复操作；运行相关测试、类型检查、Lint、构建及页面可用性检查；修复发现的问题并更新使用说明。 | 关键流程实际通过，检查结果和未完成项有真实记录。 |

模型名称、接口地址和 API Key 由项目负责人提供。在拿到配置前，可以先完成前三阶段及第四阶段的知识库和降级提示；模型生成指导须在接通后单独验证。本计划不安排安全风险评估或部署验证。

**当前执行边界：** 只实施第一阶段。模拟练习状态机、完整练习页面、AI 指导和语音朗读按后续阶段依次开发，不在第一阶段提前实现。
