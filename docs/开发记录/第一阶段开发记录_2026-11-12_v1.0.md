# 点点会第一阶段开发记录

**版本：** V1.0  
**日期：** 2026 年 11 月 12 日  
**依据：** [开发计划 V1.1](点点会开发计划_2026-11-12_v1.1.md)

## 需求与本轮指令

项目负责人确认第一版为 React + TypeScript + Vite 移动端优先响应式 Web 应用，手机竖屏优先，仅包含医院挂号、公交乘车码、扫码支付三个模拟场景；本轮只执行开发计划第一阶段。前后端分离，本地开发应支持电脑和同一局域网内手机访问。原文档中冲突的应用形态要求需更新并保留旧版本。项目负责人已授权小步提交并推送。

## 本轮实际改动

1. 保留概要设计 V1.1、详细设计 V1.0 和开发计划 V1.0，新增概要设计 V1.2、详细设计 V1.1、开发计划 V1.1，并更新根目录 `AGENTS.md` 的应用形态与阶段边界。
2. 建立 FastAPI 应用、MySQL 本地配置、三个版本化场景的演示数据和幂等初始化脚本；提供健康检查及场景列表接口。
3. 建立 React + TypeScript + Vite 手机应用式基础页面，读取场景接口并显示加载、失败、空数据与三个场景状态；练习入口明确标记“练习准备中”。Vite 监听局域网地址，并把 `/api` 代理到本机 FastAPI。
4. 增加环境变量模板、依赖锁文件、后端接口测试和本地运行指南。

## 验证与修复

- MySQL 8.4 容器健康检查通过；初始化脚本第一次写入 3 条场景，第二次写入 0 条，未重复插入。FastAPI 接口与 Vite 代理接口都返回这 3 条演示场景。
- 后端 `pytest`：2 项通过；Python `compileall` 通过。测试期间出现 Starlette 关于 `httpx` 客户端参数的第三方弃用警告，不影响本轮结果。
- 前端 TypeScript 类型检查、ESLint 和 Vite 构建通过。将初始 ESLint 9 配置更新为 ESLint 10 后，相关弃用提示消失。
- 使用 Chromium 检查 390px 手机、320px 窄屏和 1280px 桌面宽度；三个场景均显示，页面无横向溢出。通过将根字号设为 200% 检查放大效果，发现编号与标题贴近，随后调整场景编号列和间距；390px 与 320px 下复查通过。
- 从本机通过 `127.0.0.1` 和容器网络地址访问 Vite 页面及 `/api` 代理成功。未使用实体手机在实际局域网内验证，手机访问还取决于实际网络与电脑防火墙设置。

本阶段没有实现三个场景的练习流程、AI 指导或语音朗读；这些属于开发计划的后续阶段。
