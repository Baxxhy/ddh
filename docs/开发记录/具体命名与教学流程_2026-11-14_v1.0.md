# 具体命名与教学流程

版本：V1.0  
日期：2026-11-14

项目负责人要求不再使用“演示医院、演示XX”的名称，改为具体名字，并在练习之前增加教学环节。

当前2.1场景采用青禾医院、安和医院、晨光便利店、邻里水果店及具体周一时段。JSON资料以新版本写入MySQL；保留旧版本和会话，重复初始化新增0条。稳定ID、层级关系、金额目标和状态机规则保持原有业务含义。

新增只读教学接口，从当前数据库配置与同一套状态机生成六步医院、五步公交、五步支付教学。每步包括说明、操作示意、目标选项与既选摘要；支付金额示例按整数分生成。教学不写practice_sessions。前端流程为场景说明→开始教学→上一步/下一步→开始练习；最后才调用真实会话创建接口，初始选择为空、revision为0。练习不展示教学指引。

新名字在任务、选项、教学及结果中一致。移除前端残留的演示前缀；此前移除的重复模拟声明保持不显示。使用Taro UI列表，不接入AI、RAG、LangGraph或语音。端口维持5200。

初次验证发现支付教学仍含旧的“选择演示收款码”动作名称，改为“选择收款码”；ESLint发现全角空格，改为常规空格后通过。未删除测试或放宽业务校验；旧用例改用新名称，并在开始练习前真实走完教学。

实际验证：后端59项通过（含真实MySQL），浏览器68项通过，类型检查、ESLint和构建通过。新增验证覆盖教学只读、数据库标签/金额来源、教学上下步、失败重试、教学期间不创建会话及练习从零开始。已查看390px教学页面截图；五种宽度和字号检查、键盘流程均包含教学入口。
